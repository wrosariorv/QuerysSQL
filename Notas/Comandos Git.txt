**********************************

5.1)	git diff
Sirver para diferenciar un archivo tenga diferenciar, el archivo deber esta con la M de Modify.

5.2)	git diff --staged
Compara los campios de una archivo con M de Modify contra el Staged

5.3)	git commit --amend -m "Intalaciones actualizada"
comando par modificar el mensaje del commit, solo para el ultimo commit realizado

5.4)	git reset --soft HEAD^(opcional 2,3,4,etc)
Comando para modificar un commit anterior, en caso de quere 2 commit anterior al ultimo se debe agrear el numero.
basicamente lo que pasa es que se saca del stage todos los comit hasta el punto que indiquemos permitiendo hacer un comiit nuevo con modificacion que deseemos
el parametro soft lo que indica es que no se haran modificaciones destructivas.
otra forma de hacerlo con el hash largo o corto es:
		git reset --soft 13248c3

OjO: si alata un warnin indicando: LF will be replace by CRLF in historia/batman.historia.md. the file will have its original line endings in your working directory.
se soluciona corriendo el comando: git config core.autocrlf true

**6)Viajes en el tiempo resets y reflog **
******************************************

6.1)	git reset --mixed db37df0
comando usado para volver en el tiempo a un punto deseado sim que saque las modificaciones realizadas en el codigo.
el paramentro mixed no es destructivo pero saca todo del stage para que se puedo volver a commitear.
por defecto el git reset db37df0 viene con el parametro"--mixed"

6.2)	git reset --hard 	db37df0
comando usado para volver en el tiempo a un punto deseado pero haciendo las modificaciones necesarias para que el codigo quede tal cual al punto del tiempo deseado.
el paramentro hard es destructivo va a dejar el repositorio talcual al punto del tiempo deseado.

6.3)	git reflog
Comando usando para ver en orden cronologico todos los comando realizados.

teniendo el hash largo o corto puede hacer un git reset --hard 	1ee019b para moverte hasta el punto deseado

6.4)	git mv destruir-mundo.md salvar-mundo.md
comando para mover un archivo en este caso al mismo directorio y renombrando el archivo esto agregar una R de renamed

6.5)	.gitignore
Este archivos se cresa usualmente en el directorio raiz y se usa para idicar a que directorios o archivos no debe dar seguimiento
dentro del archivo .gitignore para ignorar un directorio se esccribe:

**8)Git Stash y Git Rebase- Cambios de emergencia **
****************************************************	
Stash:
Es un lugar en donde se puede mover todos los cambio incluso cambio de archivos que aun no se le da seguimiento. 
Este lugar almacenara todos los cambios en el que se estuvo trabajando desde el ultimo commit realizado. al realizar un Stash volvemos al ultimo punto commiteado.
si se esta trabajando con ramas no es muy obligatorio hacer Stash

Rebase:
Permite unir commit, separa commit, squatch "chocar dos commit", renombrar los nombre de los commit

8.1)	git stash
comando para hacer un stash de el directorio tal cual como se encuentrar en ese momento
WIP: working in progress

8.2)	git stash list
Se lista todos los stash realizados

8.3)	git stash pop
Recuperar el ultimo stash y lo elimina

8.4)	git stash clean
borra todos los stash de manera forzada

8.5)	git stash apply stash@{2}
recupera el stash numero 2.
OjO: el ultimo stash realizado siempre sera el 0 y amedida que se vayan creando se van desplzando secuencialmente

8.6)	git stash drop
Elimina el ultimo stash realizado {0}

8.7)	git stash drop stash@{1}
Elimana un stash en particular.

8.8)	git stash save "Agrego stash pepito al staged"
comando usado para guardar un stash al stage e identificar

8.9)	git stash list --stat
Lista los stash con mas infromacion

8.10)	git rebase master

8.11)	git rebase -i HEAD~4

configuracion incial para indicar que paramentros usar para hacer un push

master: es la rama que nosotros deseamos enviar al repositorio

9.6)	git pull

9.7)	git pull origin main
comando par ahacer los pull pero idintificando los origenes y destinos (fetch,push)

9.8)	git remote -v

comando usado para clonar repositorio

9.11)	git config pull.rebase true
comando usado para configurar de manera local que al haber incosistencia entre git local y github, tengamos un archivo modificado en git hub y que localmente. estos se puedan juntar o elegir el que corresponda

9.13)	git config --global pull.rebase true
